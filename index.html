INTRODUCCIÓN COMPLETA A LOS TELEPROCESOS

Definición y Contexto Histórico

Los teleprocesos (teleprocesamiento) representan la evolución natural de los sistemas informáticos centralizados hacia la comunicación distribuida. Surgieron en las décadas de 1960-1970 como respuesta a la necesidad de conectar terminales remotas con computadores centrales (mainframes) para procesar transacciones en tiempo real.

Características Fundamentales:

  • Procesamiento Remoto: Capacidad de ejecutar operaciones en un computador central desde ubicaciones geográficamente dispersas
  • Tiempo Real: Respuesta inmediata a las solicitudes (generalmente en segundos o menos)
  • Interactividad: Diálogo continuo usuario-sistema
  • Centralización: Un solo punto de procesamiento con múltiples puntos de entrada

Importancia en la Evolución Tecnológica

Los teleprocesos marcaron el camino hacia:

  • Sistemas transaccionales modernos
  • Arquitectura cliente-servidor
  • Computación en la nube
  • Aplicaciones empresariales distribuidas

COMPONENTES DE HARDWARE DETALLADOS

1. Computador Central (Mainframe)

Características técnicas:

  • Alta capacidad de procesamiento (para su época)
  • Gran almacenamiento en discos y cintas
  • Múltiples procesadores trabajando en paralelo
  • Sistemas de respaldo y redundancia

Ejemplos: IBM System/360, System/370

Funciones específicas:

  • Procesamiento de todas las transacciones
  • Almacenamiento centralizado de bases de datos
  • Gestión de recursos del sistema
  • Ejecución de aplicaciones empresariales críticas

2. Front-End Processor (FEP) - Procesador Frontal

Propósito principal:

Descargar al computador central de las tareas de comunicación para que se dedique exclusivamente al procesamiento.

Funciones detalladas:

  • Gestión de Líneas: Control de múltiples conexiones simultáneas
  • Control de Protocolos: Implementación de SDLC, BSC, etc.
  • Detección/Corrección de Errores: Verificación de integridad de datos
  • Multiplexación: Combinación de múltiples señales en un solo canal
  • Buffering: Almacenamiento temporal de datos en tránsito

3. Terminales Remotas

Tipos y características:

  • Terminales "Tontas":
    • Solo capacidad de entrada/salida básica
    • Sin procesamiento local
    • Ejemplos: IBM 3270, DEC VT100
  • Terminales Inteligentes:
    • Capacidad de procesamiento limitado
    • Validación básica de datos
    • Almacenamiento temporal
  • Dispositivos Especializados:
    • Cajeros automáticos
    • Terminales punto de venta (TPV)
    • Estaciones de trabajo industriales

4. Módems y Equipos de Comunicación

Tecnologías empleadas:

  • Módems Analógicos: Conversión digital-analógico para líneas telefónicas
  • Módems de Banda Ancha: Para conexiones dedicadas de mayor velocidad
  • Multiplexores: Combinación de múltiples canales
  • Concentradores: Agregación de tráfico de múltiples terminales

SOFTWARE DE SISTEMAS DE TELEPROCESO

Sistemas Operativos de Mainframe

Características clave:

  • Multiusuario: Soporte para cientos de usuarios concurrentes
  • Multitarea: Ejecución de múltiples procesos simultáneamente
  • Tolerancia a Fallos: Mecanismos de recuperación automática
  • Gestión de Recursos: Asignación eficiente de CPU, memoria, E/S

Ejemplos específicos:

  • IBM MVS/OS: Para sistemas IBM System/370
  • IBM VSE: Versión más pequeña para sistemas medianos
  • Unisys OS 2200: Para mainframes Unisys

Monitores de Teleproceso (TP Monitors)

Funciones principales:

CICS (Customer Information Control System) - El estándar de IBM:

  • Gestión de transacciones en línea
  • Control de concurrencia y bloqueos
  • Manejo de seguridad y auditoría
  • Administración de recursos de aplicación
  • Recuperación ante fallos

Características avanzadas de CICS:

  • Programación Transaccional: Unidad lógica de trabajo (LUW)
  • Gestión de Estados: Mantenimiento de contexto de usuario
  • Comunicación entre Programas: Paso de mensajes y datos
  • Interfaces de Usuario: Soporte para diferentes tipos de terminal

Sistemas de Bases de Datos

Características:

  • Transaccionales ACID (Atomicidad, Consistencia, Aislamiento, Durabilidad)
  • Altas prestaciones para múltiples usuarios
  • Mecanismos de bloqueo y concurrencia
  • Respaldo y recuperación en línea

ARQUITECTURA DE COMUNICACIONES

Topologías de Red Detalladas

Topología en Estrella

Ventajas:

  • Fácil administración y diagnóstico
  • Centralización del control
  • Aislamiento de fallos (un problema no afecta a otros nodos)

Desventajas:

  • Punto único de fallo (el centro)
  • Alto costo de cableado
  • Limitaciones de escalabilidad

Topología Punto a Punto

Aplicaciones:

  • Conexiones entre centros de datos
  • Enlaces de respaldo
  • Comunicación mainframe-mainframe

Topología Multipunto (Bus)

Implementación:

  • Múltiples terminales compartiendo un canal común
  • Protocolos de sondeo (polling) para acceso al medio
  • Eficiente en costos para áreas geográficas extensas

Medios de Transmisión

Líneas Conmutadas (Dial-up)

  • Uso de red telefónica conmutada (RTC)
  • Establecimiento de llamada por marcado
  • Baja velocidad (300-9600 bps inicialmente)
  • Costo variable según uso

Líneas Dedicadas

  • Conexión permanente punto a punto
  • Mayor velocidad y calidad
  • Costo fijo independiente del uso
  • Tipos: 2 hilos, 4 hilos, digitales (T1/E1)

Redes Públicas de Datos

  • X.25 (estándar temprano para redes de datos)
  • Frame Relay (evolución de X.25)
  • Redes digitales RDSI

PROTOCOLOS DE COMUNICACIÓN ESPECÍFICOS

Protocolos Orientados a Carácter

BSC (Binary Synchronous Communications)

Características:

  • Comunicación half-duplex
  • Control de enlace por caracteres de control
  • Detección de errores por BCC (Block Check Character)
  • Formato de trama: SOH, HEADER, STX, DATA, ETX, BCC

Limitaciones:

  • No soporta transmisión full-duplex
  • Eficiencia reducida en enlaces satelitales
  • Complejidad en el control de errores

Protocolos Orientados a Bit

SDLC (Synchronous Data Link Control)

Desarrollado por IBM para SNA:

  • Comunicación full-duplex
  • Operación en modo normal y respuesta
  • Tipos de estaciones: Primaria, Secundaria, Combinada
  • Estructura de trama: Bandera, Dirección, Control, Datos, FCS, Bandera

HDLC (High-level Data Link Control)

Estandarización ISO:

  • Basado en SDLC de IBM
  • Múltiples modos de operación
  • Soporte para configuración balanceada y no balanceada

MODELO OSI APLICADO A TELEPROCESOS - CAPA POR CAPA

Capa 1 - Capa Física

Funciones Detalladas:

  • Especificación mecánica de conectores (RS-232, V.35)
  • Definición eléctrica de señales (niveles de voltaje, impedancia)
  • Características funcionales (pines de control, timing)
  • Especificación de medios (cable coaxial, par trenzado, fibra)

Ejemplos en Teleprocesos:

  • Interface RS-232: Para conexiones seriales a 19.2 Kbps
  • Módems V.22/V.32: Para comunicación telefónica
  • Tarjetas de Comunicación: En mainframes y FEPs

Capa 2 - Capa de Enlace de Datos

Subcapas:

  • LLC (Logical Link Control): Control de flujo, secuenciamiento
  • MAC (Media Access Control): Acceso al medio físico

Protocolos Específicos:

  • SDLC/HDLC para líneas síncronas
  • BSC para comunicación bisíncrona
  • LLC Tipo 1, 2, 3 para diferentes calidades de servicio

Funciones en Teleproceso:

  • Delimitación de tramas y transparencia de datos
  • Control de errores por CRC-16 o CRC-32
  • Control de flujo entre FEP y terminales
  • Secuenciamiento de tramas para integridad

Capa 3 - Capa de Red

Funciones Extendidas:

  • Direccionamiento Lógico: Identificación única de dispositivos
  • Encaminamiento: Determinación de la mejor ruta
  • Fragmentación y Ensamblado: Adaptación a diferentes MTUs
  • Control de Congestión: Prevención de saturación de red

En Teleprocesos:

  • Protocolos de red en arquitecturas SNA, DECnet
  • Ruteo entre múltiples FEPs y controladores
  • Conmutación de paquetes en redes X.25

Capa 4 - Capa de Transporte

Servicios Ofrecidos:

  • Multiplexación: Múltiples sesiones sobre una conexión de red
  • Segmentación: División de mensajes grandes en segmentos
  • Control de Flujo Extremo a Extremo
  • Recuperación de Errores a nivel de transporte

En Sistemas de Teleproceso:

  • Garantía de entrega de transacciones completas
  • Control de flujo entre aplicaciones cliente y servidor
  • Mecanismos de retransmisión y timeout

Capa 5 - Capa de Sesión

Servicios Detallados:

  • Control de Diálogo: Semi-dúplex, dúplex completo
  • Sincronización: Puntos de verificación para recuperación
  • Gestion de Tokens: Control de turnos en comunicación
  • Gestion de Excepciones: Notificación de condiciones anormales

En Teleprocesos:

  • Establecimiento de sesión entre terminal y aplicación
  • Control de quién transmite en cada momento
  • Mecanismos de recuperación de sesión ante fallos

Capa 6 - Capa de Presentación

Funciones Específicas:

  • Traducción de Codificación: ASCII ↔ EBCDIC
  • Compresión de Datos: Para optimizar ancho de banda
  • Cifrado: Protección de información sensible
  • Formateo de Datos: Estructuras de datos complejas

Ejemplos Prácticos:

  • Conversión automática entre formatos de mainframe y PC
  • Compresión de pantallas para reducir tiempo de respuesta
  • Cifrado de datos financieros en transacciones

Capa 7 - Capa de Aplicación

Elementos en Teleprocesos:

  • Servicios de Aplicación:
    • FTAM (File Transfer Access and Management): Transferencia de archivos
    • VT (Virtual Terminal): Emulación de terminales
    • MHS (Message Handling System): Correo electrónico
    • DS (Directory Services): Directorio de recursos
  • Aplicaciones Empresariales:
    • Sistemas transaccionales (CICS, IMS/TM)
    • Sistemas de reservas (SABRE, Amadeus)
    • Aplicaciones bancarias (cajeros automáticos, banca en línea)

FLUJO COMPLETO DE UNA TRANSACCIÓN

Ejemplo Detallado: Consulta de Saldo Bancario

Fase 1: Inicio de Sesión

  • Usuario conecta terminal y establece comunicación física
  • Terminal negocia parámetros de comunicación con FEP
  • Sistema autentica usuario y establece sesión segura
  • Aplicación presenta pantalla inicial de menú

Fase 2: Captura de Transacción

  • Usuario selecciona "Consulta de Saldo" e ingresa datos
  • Terminal valida formato localmente (si es inteligente)
  • Datos se formatean según protocolo de aplicación
  • Se añaden encabezados de capas 6 y 7 (presentación y aplicación)

Fase 3: Transmisión hacia el Mainframe

  • Capa 5 (Sesión): Establece contexto de transacción
  • Capa 4 (Transporte): Segmenta datos si es necesario
  • Capa 3 (Red): Añade direccionamiento lógico
  • Capa 2 (Enlace): Crea trama con control de errores
  • Capa 1 (Física): Transmite bits por el medio físico

Fase 4: Procesamiento en Mainframe

  • FEP recibe y verifica tramas (capas 1-2)
  • Sistema operativo procesa capas 3-4
  • CICS maneja sesión (capa 5) y presentación (capa 6)
  • Aplicación bancaria procesa transacción (capa 7)

Fase 5: Respuesta al Usuario

  • Mainframe genera respuesta con saldo actual
  • Proceso inverso de encapsulación por las 7 capas
  • Terminal recibe y presenta información al usuario
  • Sesión permanece activa para próximas transacciones

EVOLUCIÓN Y LEGADO

Transición hacia Arquitecturas Modernas

De Teleprocesos a Cliente-Servidor:

  • Terminales tontas → PCs inteligentes
  • Mainframes centralizados → Servidores distribuidos
  • Protocolos propietarios → Estándares abiertos (TCP/IP)
  • Aplicaciones monolíticas → Servicios web

Influencia en Tecnologías Actuales:

  • Cloud Computing: Evolución de la centralización
  • Microservicios: Versión moderna de transacciones CICS
  • APIs REST: Sucesor de interfaces de aplicación
  • Contenedores: Aislamiento similar a regiones CICS

Lecciones Aprendidas y Vigentes

Principios que Siguen Aplicándose:

  • Separación entre presentación, lógica y datos
  • Importancia de la consistencia transaccional
  • Necesidad de mecanismos de recuperación
  • Valor de la estandarización en comunicaciones

Esta explicación extendida muestra cómo los teleprocesos y el Modelo OSI formaron la base tecnológica sobre la que se construyeron los sistemas distribuidos modernos, estableciendo principios de diseño que siguen siendo relevantes en la arquitectura de sistemas actuales.
